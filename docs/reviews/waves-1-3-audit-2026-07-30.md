## Two spec errors — planner owns these, not dev misses

1. **Note 5b placement.** The spec said the harvest calc goes *"inside the inputs/contact group."* That is XPath-wrong — from `/data/inputs/contact/x`, `../inputs/contact/name` would resolve to `/data/inputs/contact/inputs/contact/name` and dangle. The dev correctly placed it **after `end group inputs`** and pinned the deviation in a test. Spec corrected; scored as PASS.
2. **Note 6 emitter.** The spec said *"`Utils.getMostRecentReport`-style JS."* Wrong runtime: `Utils` is global in **tasks/targets only**. contact-summary's globals are `contact`, `reports`, `lineage` (the repo's own templates state this); helpers come from `contact-summary-extras.js` via destructure. The dev followed the spec into the P0 bug below. Memory + spec updated.

## Fix queue (ranked)

### P0 — must fix before anyone uses this (Wave-3 blocker + Wave-1 regression)

1. **[W3·6 — RUNTIME BLOCKER] Bridge emitter references `Utils`, which doesn't exist in contact-summary.** `contextValuesParser.ts:113-114` emits `Utils.getMostRecentReport(reports, …)` / `Utils.getField(…)`. On device: `ReferenceError` → the **whole `context` object dies** (contact page + every form's `instance('contact-summary')` read), and the form-side `if(ref, ref, .)` wrapper *masks* it as "no report yet." Compiles clean — nothing catches it pre-device. **Fix:** emit a self-contained `reports` scan (inline filter/reduce over `reports`, newest by `reported_date`, then walk `report.fields.<path>`) — or emit + guarantee an extras helper (`getNewestReport` destructure). Coordinated change: `BRIDGE_RE` (`:72`), the emitter (`:108-117`), `contextValuesParser.test.ts`, `contactSummaryParser.test.ts:233` (currently asserts the `Utils.` string!).
2. **[W1·1 — HIGH regression] Hyphenated basenames are now impossible → manual contact-form creation broken.** The create path funnels everything through `slugifyHierarchyId` (maps `-`→`_`), but this repo's own contract requires contact forms on disk as `<type>-create.xlsx` (`buildContactForm.ts:17-20`, `contactFormBasename`; the batch generator still enforces the hyphen shape at `forms.ts:541-551`). The dialog's own placeholder "Household — create" now yields `household_create`. **Fix:** preserve `-` when `category === 'contact'` (derive `<slug>-create` shape), or restore an advanced "exact filename" field for contact forms.
3. **[W3·6 — silent data loss] Context save is gated on the active tab.** `ContactSummaryEditor.tsx:223-229` only writes context edits when `view === 'structured' || 'values'` — add a context value, switch to Cards/Raw, hit Save → the edit is dropped AND the dirty flag clears. **Fix:** track `contextDirty` (edit-based, not view-based).

### P1 — breaks the feature's own promise

4. **[W3·6] Context-key cache never invalidates** (`useContactSummaryContextKeys.ts:42-44,75-78`, module-level cache, no invalidation anywhere). The feature's own loop — empty state → deep link → define value → back to calc builder — shows stale "No cross-form values defined yet" until a full reload. Invalidate on contact-summary save (mirror `parsedFormCache.invalidate` style).
5. **[W3·6] Field picker emits bare leaf names** (`useReportFormFields.ts:33-48`) — a grouped source field (`vitals/bmi`) produces `getField(report, 'bmi')` → `undefined` at runtime, silently masked by the wrapper. Emit the group-qualified dotted path (parser + tests already support dotted paths).
6. **[W2·3b] Section create on a non-`en` form injects a stray `label::en` column + mislocated title.** `seedLabels` fallback hard-codes `out['en']` (`FormEditor.tsx:884-886`) because `sectionMode` collects a single title, not per-locale labels (`QuestionTypePicker.tsx:276-297`); accordion header also hard-codes `labels['en']` (`:1801`). **Fix:** give the section dialog the same per-locale label inputs item 4 gave questions (compose 3b with 4a); header falls back through active locales.
7. **[W2·3b] Empty-group drop-zone is decorative.** One flat `SortableContext` (`FormEditor.tsx:1333`), zero `useDroppable` for group containers — a drop lands *outside* the group. Either wire a real droppable per group or reword the placeholder to the (working) `+ Add question` only. The spec's "create-empty + drag-in" promise currently holds only for the button half.
8. **[W3·6] Unvalidated bridges are saveable.** New value seeds `sourceForm:''`/`sourceField:''` and `save()` never validates (comment at `ContactSummaryEditor.tsx:258-261` claims otherwise); `renameFlag` (`:145-154`) accepts XPath-illegal keys (test even blesses `'0-latest-visit'` — unreadable via `instance(...)`). Same class as the Wave-1 save-gate: validate at save, identifier-check renames.
