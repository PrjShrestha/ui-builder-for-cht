# CHT project (empty)

Generated by the CHT UI Builder from the **Empty** template. Nothing is
pre-defined — the contact hierarchy, contact types, tasks, contact-summary
context, and forms are all yours to build from zero.

## What this ships

- `app_settings/base_settings.json` — English locale, **empty**
  `contact_types[]` and `place_hierarchy_types[]`. Edit `default_country_code`
  and `phone_validation` for your region.
- `tasks.js` — empty array (no task rules).
- `contact-summary.templated.js` — returns an empty `context` object;
  no fields, no cards.
- No forms. `forms/app/` and `forms/contact/` are created the moment you
  add your first form through the UI.

## Where to start

Open the project in the UI Builder. Suggested order:

1. **Hierarchy** — add your top-level place type (no parent), then work
   downward. The topological order is recomputed for you on every edit.
2. **Forms → ✨ Create new** — scaffold your first contact form (so the
   place types are creatable in the app) and your first app form.
3. **Contact summary** — add context flags that gate which forms appear
   on a person's profile.
4. **Tasks** — add task rules that fire after specific forms are submitted.
5. **Deploy** — Validate everything (no upload), then deploy to a CHT
   instance via the Deploy panel.

## Deploy from the CLI

```sh
cht --local compile-app-settings
cht --local convert-app-forms
cht --local upload-app-settings upload-app-forms
```
