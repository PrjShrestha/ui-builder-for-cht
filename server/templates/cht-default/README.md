# CHT baseline

Generated by the CHT UI Builder from the **CHT baseline** template — an
import of cht-core's `config/default/` ([source](https://github.com/medic/cht-core/tree/master/config/default)).

This is a **complete reference configuration** maintained by the CHT core
team. It's the same code that powers the default CHT instance, ready to
deploy as-is or to adapt.

## What this ships

- **Hierarchy:** `district_hospital → health_center → clinic → person` (4
  contact types).
- **app_settings:** the full ~100 KB CHT default — locale, country code,
  permissions, roles, transitions, purge config, UHC settings, schedule
  windows, etc.
- **tasks.js + tasks-extras.js** — pregnancy / immunization / follow-up
  task rules with a full helpers library. (Renamed from cht-core's
  `nools-extras.js` so the Tasks editor finds it.)
- **contact-summary.templated.js + contact-summary-extras.js** — context
  flags, fields, and cards for person and place profiles.
- **targets.js** — analytics targets the CHT app evaluates. (Read-only
  in this build — see the v0.1 README for what's editable.)
- **forms/app/** + **forms/contact/** + **forms/training/** — the
  reference CHT forms (pregnancy registration, ANC follow-up,
  immunization, delivery, death reporting, family planning, training).
- **translations/messages-en.properties** — English UI strings used by
  the templates above.
- **resources/** + **resources.json** — icon assets referenced by the
  contact types and forms.

## Where to start

Open the project in the UI Builder. Suggested order:

1. **Overview** — confirm everything was detected (app_settings, forms,
   tasks, contact-summary all green).
2. **Hierarchy** — review the 4-type hierarchy; rename or extend it for
   your program (e.g. add `community_health_volunteer` between
   `health_center` and `clinic`).
3. **Forms** — explore the existing pregnancy / immunization / FP forms;
   adapt their `relevant`, `calculation`, and labels to your context.
4. **Tasks** — adjust schedule windows, task names, and `appliesIf` rules
   to match your program.
5. **Contact summary** — tailor the cards and context flags that determine
   when forms appear.
6. **Deploy** — Validate everything (no upload), then deploy to your CHT
   instance.

## A note on country / locale

This template ships `default_country_code: 1` and English-only locales.
Update `app_settings/base_settings.json` for your region before you go
live.

## Deploy from the CLI

```sh
cht --local compile-app-settings
cht --local convert-app-forms convert-contact-forms
cht --local upload-app-settings upload-app-forms upload-contact-forms upload-resources upload-translations
```

Or click through the Deploy panel in the UI Builder (the macro
**Deploy everything** runs the chain above against `--local` by default).
